# Changelog

The app currently reports itself as v1.5.0 (Settings > About / Updates).

## Unreleased

### Added
- **Now Island: background tasks and Peek** (build-order item 5; UI/UX spec feature 14). Anything that takes a while is now listed in **Now Island > Now** under **RUNNING**, and finished work under **RECENTLY FINISHED** (60 seconds, a Clear link, a dismiss cross on each). A row has the kind icon, the title, a second line (*Running 00:42, in another tab*), and **Peek**, Go to and Stop where they apply; a 2px line along its bottom edge is the progress (indeterminate shimmer when there is no percentage). **Peek** opens under the row, inline and without taking focus: the elapsed time, the last four lines of output (monospace, errors in red, all as plain text), Stop, **View full output** (the same slide-over the notifications use; it follows new output; Esc or Back closes it) and a pin. **Pin to screen** detaches the task into a **floating Peek panel** (320px, bottom right, draggable by its header, up to three then "+N more") that stays after the island closes and does not block clicks around it; it is hidden while the island is open. A success fades after 8 seconds unless hovered or kept (*Keep open*); a failure stays until closed and offers **Open**. On a phone the panels are a one-line strip beside the activity bar (two at most, a swipe to the right dismisses). The status-bar Now Island button shows a spinner and the running count instead of its icon, flashes a check or cross for about a second when something ends, and says "2 running, 1 unread" in its tooltip; a background window's tab gets a small spinner. No animation under *reduce motion*.
  - **What reports to it today:** Git push, pull and fetch (with the step text, "Fetching 12/48: path", and a percentage), Console runs, Terminal runs, the editor's Run (Stop works for Console and editor runs, as their own Stop does), notebook runs (one task per notebook for Run All, with progress and the current cell; a cell run on its own is a task for the length of that cell; Stop presses the notebook's Interrupt Kernel) and Download > ZIP (with progress). `window.CodeMiniBackground.start({ kind, title, ... })` is the one call a new feature makes (Deploy, Tasks, tests, Agent Mini and Database are next); its rules are at the top of `js/core/background-tasks.js`.
  - **When something is shown:** a task is listed once it has run 800 ms, or at once if it starts while the app is hidden or another window is active, so a one-line Console command never flashes the status bar. Whether the person is looking is asked again every second and on visibility changes. A task that was out of sight at any point adds a notification when it ends (and a toast if the island is closed); one that was watched does not, and neither does a Stop the person asked for. Git and notebook runs announce themselves already and are not announced twice.
- The shared `.sb-section-header` and `.sb-count-badge` classes (values copied from Source Control's, which is untouched), as the specs ask, in `css/style.css`. Note that `.sb-color` and `.sb-reset-btn` already in that file mean the *status bar*'s color settings; the new `sb-` means *sidebar*.

- **Keyboard shortcut editor** (Settings > Keybindings). Twelve commands now live in one registry (`js/core/keybindings.js`) and each row shows its name, what it does, when it applies, whether the key is the *Default* or *User*, and its keys. Hover a row for a pencil: press the keys you want (the box shows them as you hold Ctrl, Shift and Alt), then Enter to keep or Esc to cancel; a cross removes the shortcut, and a reset icon brings back the default. **Reset all** asks first. Changes are saved per window / profile with the other settings, and the Settings search box finds a shortcut by name. A shortcut needs Ctrl or Alt, or is a function key (Shift with Enter, Tab or an arrow also works), because a bare letter would fire while you type. Warnings, not refusals: a key another command already has (\"Also used by Toggle Sidebar\"; Run Cell and Commit may share Ctrl+Enter because they apply in different places), a key the browser keeps for itself (Ctrl+N, Ctrl+T, Ctrl+W and a few more, which is why New File is Alt+N), and Ctrl+Alt, which many keyboards use for AltGr. The terminal's, console's and mini editor's own keys and Open to the Side are listed under *Fixed shortcuts*.
- **Snippets** (Settings > Snippets, after Editor). Snippets are kept per language in the VS Code format (`prefix`, `body`, `description`) and offered in autocomplete with the snippet icon; Tab expands one, with tab stops (`$1`, `${2:name}`). A language picker, a New Snippet form (name, prefix, description, body) that adds to the file and is one undo, and the language's file in a Monaco editor with schema checks (a snippet with no prefix is underlined and skipped; text that is not JSON is not saved and the last good version stays in use). The picker counts snippets per language and lists those with snippets first, and reopening Settings returns to the language you were on. A prefix with a dash (`for-each`) replaces what you typed instead of being added to it.
- **Settings (JSON)**: a `{ }` button at the top right of Settings, or Quick Open > *Open Settings (JSON)*, opens `settings.json`: every setting with its current value, in the order of the defaults, in a code editor whose schema is built from the Settings screen's own controls (type, allowed options, number range), so a wrong value or an unknown name is underlined as you type. **Ctrl+S applies it**, and only then (autosave never does). Nothing is applied while anything is wrong, so a half-edited file cannot change half your settings; only the settings you changed in the file are applied (so changing another in the Settings screen meanwhile is not undone), and a setting you delete is left as it is. Security settings (isolation, Workspace Trust, the sync switch) are not in the file: they stay in Settings > Security. The tab has no file behind it, and comes back after a reload as a fresh copy.
- Quick Open commands: *Open Keyboard Shortcuts*, *Configure Snippets*, *Open Settings (JSON)*.
- **Status bar colors** (Settings > Theme > Status Bar). One row with two swatches, *Background* and *Text & icons* (the text and the icons share one color), and a *Reset* button. They apply to the status bar on Light, Light +, Dark and Dark +. Under a Theme Pack nothing is applied and the bar looks as the pack draws it; your choice is kept and comes back when the pack is set to None, and the swatches are locked while a pack is on. Nothing is chosen by default, so the bar is unchanged until you pick a color. Choose only a background and the text and icons switch to black or white, whichever reads better on it. The warning icons (auto save off, restricted mode) keep their own yellow. The settings are `statusBarBackground` and `statusBarForeground` (empty = the theme's own, otherwise `#rrggbb`; anything else in settings.json is stored as empty). They reach the page as the CSS variables `--status-bar-bg` / `--status-bar-fg` on `<html>`, which `.status-bar`, `.status-item i` and the dark rule in `themes.css` read with the old color as the fallback, and they are in the early-paint theme cache so the next load shows them from the first frame.

### Changed
- **The Now Island panel grows with its content** (290px tall when there is little to show, 340px on a phone; at most 72vh, 60vh on a phone, then the list scrolls inside) instead of always being 290px tall. The Now tab's empty state says "Nothing is running".
- `runCell` in `js/notebook/notebook-kernels.js` is now a small wrapper around `_runCellCore` (the old body, unchanged) so a cell can report as a task; every caller still calls `runCell`.
- The app's shortcuts (New file, Close tab, Toggle sidebar, Open terminal, Search, Format, Save, Quick Open and the Command Palette) are handled by the registry instead of four separate listeners, which also means: **Cmd works on a Mac** for Toggle Sidebar, Terminal, Search and Format (only Ctrl did), Ctrl+S saves with Caps Lock on (it only saw a lower-case s), and the app takes the key before Monaco, so Shift+Alt+F no longer runs Monaco's own formatter a second time. Run Cell, Run Cell and Move On (notebooks) and Commit (Source Control) now follow the keys you set. The command palette shows the key a command has *now*, not a fixed label.

### Fixed
- **The diff tab follows the editor's settings.** It used to be created with only a font size, font family, line height, word wrap and render-whitespace, so it always showed line numbers as *on* and never noticed a change in Settings. It now takes the same line-numbers choice as the main editor (on, off, relative, interval) plus font weight, letter spacing, ligatures, tab size, smooth scrolling and bracket colorization, when it opens and live while it is open (`optionsFromSettings()` and `window.updateDiffEditorSettings()` in `js/core/diff-editor.js`). `updateMonacoGlobalSettings` (`settings-profile.js`) leaves a diff tab's two inner editors alone and updates the diff editor as a whole, because Monaco's diff editor re-applies its own options to its sides.
- **“No differences except whitespace” is only said when it is true.** It was shown for any pair of different texts with no changes, such as two files that differ only in line endings, even with *Ignore whitespace* off; it now needs the texts to match once all whitespace is removed (or the box to be ticked).
- **Download > ZIP in tree view no longer repeats files.** Ticking a folder in tree view also ticks everything inside it, and the ZIP builder then walked into the folder *and* added each ticked item again at the top level of the archive (Select all made it easy to trigger). Items whose parent folder is also selected are now skipped (`selectionRoots()` in `js/core/up-down.js`). The JSON backup already ignored repeats.
- **Download > ZIP works again.** It failed without a message. Monaco's AMD loader (in the page head) defines `window.define`, so when the ZIP code added JSZip with a plain `<script>` tag, JSZip's wrapper registered itself as an AMD module instead of creating the global `JSZip`: the script loaded without an error and `new JSZip()` then threw. The same cause was found, and fixed by hiding `define` while the page loads JSZip, in another CodeMini codebase the owner supplied (its Packager, Export and database backups failed the same way). Here `loadJSZip()` (`js/core/up-down.js`) fetches the pinned 3.10.1 file as text (the service worker caches it, so it works offline after the first use) and runs it as an inline script that wraps the library in a function whose `define`, `exports` and `module` are its own parameters, so JSZip takes its plain-global branch. `window.define` is never hidden, so Monaco modules loading at the same moment are not affected, and the loader adds no `eval` / `new Function` line (the `exec-sinks` count is unchanged). Two clicks share one download and a failed load can be retried.
- **ZIP errors are now shown.** A library that cannot be loaded (offline the first time) or a ZIP that cannot be built opens a “ZIP download failed” message; before, the click failed silently. The download link is now added to the page and its blob URL kept for four seconds (`triggerBlobDownload`): revoking it right after `click()`, as the ZIP code did, cancels the download in some browsers. The JSON export still revokes straight away (it works, so it was left alone).
- **Known limit, not changed:** *Ignore whitespace* uses Monaco's own option, which ignores whitespace at the start and end of a line. Spacing inside a line and added or removed blank lines still show as changes.

## 1.5.0 (2026-11-08)

### Added
- **Selection shortcuts in the Explorer status bar.** While Multi-Select or the Download toggle is on, the right side of the status bar (where it says *Cloud syncing* / *Syncing locally*) shows three icons instead: **Select all / Unselect all**, **Select all folders** and **Select all files**. They act on the items the Explorer is showing (so a search filter, the open folder and expanded tree folders all count), fill the Download selection when that toggle is on (it wins when both are on) and the Multi-Select one otherwise, and each is a toggle: when everything of that kind is already selected it unselects it. Unselect all clears the whole selection, including items picked in another folder. A workspace counts as a folder. The folders and files icons are disabled when there are none to select, and on touch screens the status bar grows to 34px while the icons are showing. The sync status returns when both modes are off.
- **Local History.** Every save of a code file now leaves a version behind: Ctrl+S as *Saved*, automatic saves as *Auto saved*. Automatic saves less than 20 seconds apart share one version, and saving text identical to the newest version adds nothing. **Explorer > Timeline** (above the status line, collapsed by default, and it remembers whether you opened it) lists the versions of the open file: when, how it was saved, its size, and the lines added and removed against the version before (a count of lines, so a moved line is not counted). Click a version to see it in the diff tab against the file as it is now. The icons on a row compare it with the version before it, **Restore** it, or delete it; Restore first keeps what is there now as a version, and in an open file it is one undo. The bin in the header clears a file's history after a second click. Open it from Explorer right-click > **Local History...**, a tab's right-click menu, or Quick Open > *Show Local History for Active File*. Per file it keeps the newest 50 versions for up to 14 days, and 64 MB in all (the oldest go first); text over 1 MB is not kept. Settings > Application > **Local History** has an on/off switch, versions per file, days to keep and **Clear History**. It lives in its own IndexedDB (`CodeMiniHistory`); the workspace databases and their schema are untouched.
- **Hot exit** (Settings > General > Hot Exit, on by default). About 1.5 seconds after you stop typing, unsaved text is copied aside, and the copy goes when you save or close the tab. After a reload, a crash or a closed browser, that text is back in its tab, marked unsaved, and one undo returns the tab to the saved text. Recovered text is never written to the file by itself, even with auto save on; it is saved when you save or keep typing, like any edit. A notification says *Recovered N unsaved files* and its **Review** button opens each one against its saved version; if the file changed after the copy was made (a pull, another window) it says so. A copy of a file that no longer exists is dropped. A second CodeMini window never takes over the first one's text: windows are told apart with the Web Locks API, which the browser releases when a page closes or crashes. When the page is hiding or closing, the copy is written at once instead of waiting for the pause (best effort: the browser decides how long a closing page may keep working).
- **The Timeline can be resized.** Drag its top edge (a 6px handle, the same `ns-resize` strip the bottom panel has; it also works by touch), or press Up / Down on the handle (Shift for bigger steps) and Home to go back to the default; double-clicking the handle does the same. It stops at 56px and before it would leave the file list under 120px, the height is remembered per window like the sidebar width and the bottom panel height, and in a window too short for it, it shrinks for now and returns to the chosen height when there is room again.
- **Auto Save switch** in the status bar (right group, before the Now Island button). One click turns Auto Save off or back to the mode that was on (After Delay, On Focus Change or On Tab Change), so it never resets your choice; an open Settings screen follows.
- **Closing a tab with unsaved text no longer drops it silently.** Closing still does not ask or save (unchanged), but the text typed since the last save is kept in the Timeline as *Closed unsaved*. A window switch, which closes tabs the same way, is covered too.
- **Diff editor.** A diff now opens as an editor tab (type `diff`) with Monaco's own diff editor, which the app already loads, so it works offline (the Source Control popup's diff fetched a library from a CDN at run time and still does). A slim toolbar has **Unified / Split** (remembered; Unified only under 768px, where Split is disabled), **previous / next change** with a counter ("3 of 12", wrapping at both ends), **Ignore whitespace**, and **Refresh**. Two labelled sides, "No differences" / "No differences except whitespace" when there is nothing to show, "Binary file, diff not available" for binary files, and a locked file is refused with a reason. The same diff opened twice is one tab. Ways in: **Explorer** right-click a file > *Select for Compare*, then another > *Compare with Selected*; **tab right-click > Compare with Saved** (the editor's unsaved text against what is stored; the app had no tab menu, so this adds a small one with *Close* and *Close Others*); **Source Control**: the popup gets an *Open in tab* icon and double-clicking a changed file, a conflicted file or a file in a commit opens the tab (a single click still shows the popup; a working-tree diff in a tab can be refreshed); **Quick Open**: *Compare Active File With...* (it asks for the other file using the same fuzzy list, files only) and *Compare Active File with Saved*. A diff tab is a read-only view and is not restored with a session (it has no file of its own to reopen).
- **Not in the diff editor, on purpose:** per-hunk *Stage*. Staging here is by file (the index holds only a list of paths, never content), so staging part of a file would need a different design. Per-hunk *Revert* could be added later.
- **A name already in use now asks, instead of renaming.** Copy, Cut and Paste, drag-and-drop, Move/Copy to the root, to a workspace or to another window's profile, imports (files, folders, ZIP extraction, a cloned repository, a JSON export) and restoring from the Recycle Bin used to number the newcomer `name(1).ext` every time. Now each clash opens a dialog with the existing and the incoming item side by side (name, last-modified time, size or item count, and a Newer/Older tag) and three answers: **Replace**, **Skip** or **Rename** (the old behavior, which also tells you what it will be called). With several items it is asked per item, with an **Apply this choice to all remaining items** box and a **Stop** button that cancels the whole operation before anything is written. Esc means Stop (or Skip for a single item). Replace is not a hard delete: the replaced item goes to the Recycle Bin (when it is on) and any tab open on it is closed. A whole folder is one item: Replace deletes the old folder and its contents (to the bin), Skip drops the folder and everything in it. A cut that you Stop stays on the clipboard. A copy pasted into its own folder is still just numbered, with no question.
- **What can never be replaced:** a locked item (the button is disabled and the dialog says why), an item that contains the thing being moved or copied, and a name already taken by an earlier item in the same batch (only Skip or Rename there).
- **Quick Open.** The title-bar search box is now a keyboard-first Quick Open. **Ctrl+P** (Cmd+P) opens it and **F1** or **Ctrl+Shift+P** opens it in command mode (Ctrl+Shift+P is reserved by Firefox). Matching is fuzzy: `sapp` finds `src/app.js`, `gfic` finds `getFileIcon.js`, and letters that start a word or a camelCase hump score highest. Matched letters are highlighted and each row shows its folder, cut from the left when long. Up/Down/PageUp/PageDown move, Enter opens, **Alt+Enter opens to the side** (it splits the editor if needed), Esc closes. An empty box lists **Recently opened** first. Prefixes: `>` commands (now 12, with their shortcuts shown), `:42` or `:12:5` go to a line, `@` browses the file's symbols, `#` filters workspaces, and `app.js:42` opens a file at a line. Opening a nested folder now builds its whole breadcrumb. The hint row at the top is clickable, which gives a phone the prefixes it has no key for. Rows are 44px on phones, and scrolling the list puts the keyboard away. Quick Open and Command Palette are listed in Settings > Keybindings.
- **`git` in the terminal.** The integrated terminal now has a `git` command that works on the same repository as the Source Control panel: a commit made in one shows up in the other, and so do branches, tags, stashes, staged files, a merge waiting on conflicts, and the Reflog. Commands: `status` (`-s`, `-b`), `add` (`.`, `-A`, `-u`, `-f`, patterns), `commit` (`-m`, `-a`, `--amend`, and it finishes a merge), `log` (`--oneline`, `--graph`, `--all`, `-n`, `--author`, `--grep`, `-- <path>`), `diff` (`--staged`, `<commit>`, `--stat`, `--name-only`, `--name-status`), `show`, `branch` (create, list, `-v`, `-d`, `-D`, `-m`), `switch` and `checkout` (`-c`/`-b`, `-f`, `-- <path>`, `--ours`/`--theirs` during a merge), `restore` (`--staged`, `--source`), `reset` (`--soft`, `--mixed`, `--hard`, or paths), `merge` (fast-forward, merge commit, conflicts, `--abort`), `stash` (`push -m`, `list`, `pop`, `apply`, `drop`, `clear`), `tag` (lightweight, annotated, `-d`, patterns), `reflog`, `rev-parse`, `remote -v`, `config user.name|user.email`. Revisions can be `HEAD~2`, `HEAD^`, a branch, a tag or a short commit id. Paths are relative to the folder you are in, and the output works in pipes (`git log --oneline | grep fix`). `git help` lists everything; `push`, `pull`, `fetch`, `clone`, `rebase`, `cherry-pick` and `revert` say they are in the Source Control panel.
- **It is more careful than the panel in two places, on purpose.** Switching branches or merging with uncommitted work is refused (it lists the files, and suggests `git stash` or `-f`) instead of discarding that work after a dialog. And files that `.gitignore` hides (`node_modules/`, logs) are left alone by a switch, reset or stash, where the panel's checkout deletes them.
- The terminal works on its own database, which can differ from the one the Explorer has open (a split window, or after `sync`), so `git` opens that database itself and only redraws the Explorer, the panel and the status-bar branch when it is the same one.

### Changed
- The terminal's `uname -r` and `uname -a` now print the app's own version, read from `app-info.js` when the command runs, instead of a copy written into `terminal-commands.js` that had to be edited at every release. Without `APP_INFO` they print `unknown`.
- The Explorer file menu has **Local History...**, a file tab's menu has **Local History...** (the diff editor's end-to-end test was updated to expect it), and Quick Open has a command for it. A locked file is not offered it.

### Source Control: Push is now one real push
- **Push no longer makes one GitHub commit per file.** It used to walk the whole committed tree and write every file through GitHub's Contents API, so a push of 40 files showed up as 40 commits titled "Update <path> via CodeMini", your own commit messages never arrived, and a failure midway left GitHub half-updated. It now works like `git push`: it uploads the file contents GitHub does not already have, builds a tree and a commit for each local commit being sent (with that commit's own message, and its author and date when it has a real identity), and moves the branch with a single, non-forced update at the very end. Until that last step nothing on GitHub has changed, so any failure (network, rate limit, a branch that moved under you) leaves the remote exactly as it was, and the message says so. Requests are made one at a time, as GitHub asks for writes.
- **Only what changed is sent.** The remote's file list is compared by git blob id (computed here, checked against `git hash-object` in the tests), so a file that is already up there unchanged is never uploaded again, and content GitHub already holds under another path (a copy or rename) is referenced instead of re-uploaded. Pushing with nothing new now reads from GitHub and writes nothing, and says "Nothing to push".
- **Deleting a file locally and pushing now deletes it on GitHub.** Only files removed since the last push are deleted; a file that is on GitHub but was never known to this workspace is left alone, and a file someone else already removed is not an error.
- **Which commits go up.** The last local commit pushed or pulled for each remote branch is now remembered (a new `synced_<branch>` record, trusted only for the repository it was recorded against). The next push sends the commits after it, oldest first. Merge commits go up as the single commit they are (the remote history is linear; a merged-in branch arrives through its merge commit). Into an empty repository the whole history is sent: the first file is written through the Contents API (GitHub accepts nothing else in a repository with no commits), then the rest goes up normally. The first push to a repository that already has commits, and a push after history was rewritten here (rebase, reset, amend), go up as ONE commit holding the current tree, using the tip's message; the result line says so. Mode bits (an executable stays executable) and binary files are preserved.
- **A push to a branch that does not exist on GitHub is refused** with a plain message instead of creating it. A repository GitHub cannot find (or the token cannot see) is reported as such. If GitHub reports the file list as too large to compare, files still go up but deletions are skipped, and the result says so.
- **Remote tab: a note above the buttons says what Push will send**, e.g. "Pushes the last commit on **main** (3 uncommitted changes not included).", "Pushes the 2 commits on **main** since the last push.", or "Nothing new to push". Uncommitted changes, staged or not, are never sent, and the help text now says so.
- **Fixed: the unpushed-commit count never went down.** The `↑N` badge in the status bar, the Remote tab's "N local commits not yet pushed", Fetch's result line and the Pull warning counted from GitHub's own commit id, which does not exist in the local commit store, so every commit always counted as unpushed (even right after a push). They now count from the last synced local commit. A repository that was last pushed before this version still shows every commit until its next push.
- Known limits (unchanged): auth is still a personal access token, there is one remote, no force push, and a push does not check whether someone else changed the same files on GitHub since your last fetch (a non-fast-forward is refused, but a newer commit on top of the one you saw is built upon, so the same file is overwritten). Tags are not pushed. Needs the same token scopes as before (`repo`, plus `workflow` for workflow files).
- New `tests/git-push.test.js` (40 checks, run for real against a fake GitHub that is strict about what the Git Data API accepts: missing blobs, deleting an absent path, non-fast-forward updates, the Contents API on a non-empty repository). Covers the plan (incremental, full, squash, merges), commit messages and order, deletions, binary files and modes, authorship, empty repositories (404 and 409 variants, and a repository that refuses an explicit branch), failures leaving GitHub untouched, a branch moving mid-push, the synced record, the unpushed count and the Remote tab note. ### Workspaces: a full audit of how the app adapts to them
Every workspace has its own isolated database, and a file's id only exists in one of them. A lot of code picked "the" database the wrong way (the window's outer database instead of the open one), which showed up as things silently not saving, appearing in the wrong place, or vanishing.

- **Typing in a Document inside a workspace never saved.** A Document works out where to save from the window record, which always names the OUTER database; the file only exists in the workspace's own one, so the save found nothing and quietly did nothing. File tabs now remember the database their file was opened from, and every save (Documents, code, notebooks) goes there.
- **Edits could be lost when moving between a workspace and CodeMini with a tab open.** The save looked the file up in whichever database happened to be open by then. Now, when the open database changes, unsaved edits are first saved to the database each tab belongs to and those tabs are closed (a tab only works against its own database), with a short notice.
- **Saving could create databases.** A save, search, restore or terminal command aimed at a workspace that had been deleted re-created it as an empty "ghost" database (and could block deleting it again). Those paths now open a database only if it exists.
- **Back/Forward across a workspace boundary showed the wrong files.** They restored the folder path without switching database, so a workspace's name appeared over the outer database's files (or the reverse). They now switch database first, and a workspace that has been deleted falls back to CodeMini.
- **Cut/Copy/Paste across databases.** The clipboard recorded the window's outer database as its source and Paste wrote to it, so pasting inside a workspace sent files to the outer database (invisible), and pasting between a workspace and CodeMini was treated as a same-database paste. Cross-database "cut" also never removed the original. Fixed all three; tabs of files that were moved out are closed.
- **Global search searched the outer database** even inside a workspace, and leaked a connection each search. It now searches the open database and closes the connection.
- **Recycle bin restore put files in the wrong database.** Restoring something deleted inside a workspace (from CodeMini, or another workspace) wrote it into the open database as an orphan and removed it from the bin. Deleted items now remember where they came from and are restored there; anything whose workspace no longer exists stays in the bin with a message instead of being dropped.
- **Creating a workspace:** it left a database connection open for the rest of the session (blocking deleting it), saved the new workspace into the wrong database if you were inside another workspace (so it never appeared), and allowed two workspaces with the same name. Fixed.
- **Deleting a workspace** now also forgets its saved trust decision and drops its recycle-bin entries.

### Changed
